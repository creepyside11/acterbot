# Aster Agent

Персональный ИИ-агент для VPS. Панель открывается в браузере и как Telegram Mini App. Можно отправить задачу и файлы через бота, закрыть Telegram и вернуться к результату позже.

## Что умеет

- Подключает API в формате OpenAI Chat Completions через **Base URL, API-ключ и ID модели**. Настройки меняются из панели.
- Открывает публичные HTTPS-страницы в Chromium, ищет в интернете, читает текст, переходит по ссылкам, прокручивает страницы и сохраняет скриншоты.
- Анализирует фото, если подключённая модель поддерживает изображения. Читает TXT, CSV, код, PDF с текстовым слоем, DOCX и XLSX. Для больших документов модель получает ограниченный фрагмент текста.
- Создаёт файлы результата, включая Markdown, TXT, JSON, CSV и XLSX. Их можно скачать в панели или забрать через бота.
- Составляет план, раздаёт независимые подзадачи максимум трём субагентам и собирает их результаты. План, статусы и ответы субагентов видны на странице задачи.
- Читает и сохраняет файлы в постоянной рабочей папке VPS. Готовый файл можно добавить к результату для скачивания.
- Ведёт очередь, историю и журнал в SQLite. Сохраняет прогресс после действий и продолжает с сохранённого шага при перезапуске сервера. Лимит одной задачи настраивается до 600 минут.

Браузер работает в режиме просмотра публичных сайтов. Агент берёт из очереди одну основную задачу за раз. Её субагенты работают параллельно. Для нового задания можно приложить до четырёх файлов по 8 МБ.

## Установка на VPS

Понадобятся Linux, Docker с Compose v2, Python 3 для первичной настройки и доступ VPS к реестрам пакетов, Telegram и API модели. Ориентир для одного пользователя и удалённой модели — **2 vCPU, 2 ГБ RAM и 10 ГБ свободного места**. Для локальной модели на VPS ресурсы зависят от выбранной модели.

1. Создайте бота у [@BotFather](https://t.me/BotFather). Если свой числовой Telegram ID неизвестен, выполните следующую команду, введите токен и отправьте боту `/start` по подсказке.

   ```bash
   python3 setup.py telegram-id
   ```

2. На VPS распакуйте архив, перейдите в каталог и выполните:

   ```bash
   cd AsterAgent
   python3 setup.py
   ```

   Введите публичный IP или домен, токен бота и свой Telegram ID. Сохраните пароль панели, который напечатает установщик. Для домена заранее укажите DNS-запись на VPS. Откройте входящие TCP 80 и 443 в сетевом экране VPS и панели хостинга.

3. Соберите и запустите три сервиса.

   ```bash
   docker compose --profile https up -d --build
   docker compose --profile https ps
   ```

   Caddy получает и обновляет TLS-сертификат через Let's Encrypt, в том числе для публичного IP. Сведения о выдаче сертификата видны в `docker compose logs caddy`. Telegram требует HTTPS для Mini App. [Telegram Mini Apps](https://core.telegram.org/bots/webapps) · [Сертификаты для IP](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)

4. Откройте `https://ВАШ_IP/` или адрес вашего домена и войдите с паролем панели. Откройте **Настройки**, заполните Base URL, ключ и ID модели. Нажмите **Сохранить**, затем **Проверить API**. Для браузера и файловых действий модель должна поддерживать вызов инструментов. Для фото включите анализ изображений, если модель его поддерживает. Если инструменты выключены, модель принимает текст и поддерживаемые вложения и даёт текстовый ответ. [Спецификация Chat Completions](https://developers.openai.com/api/reference/chat-completions/overview)

5. Отправьте боту `/start` и нажмите **Открыть Aster**. Бот также добавляет кнопку в меню вашего чата. Для Mini App вход выполняется по Telegram-аккаунту с указанным ID.

### Проверочная задача

> Открой https://example.com. Напиши, для чего предназначена страница, сохрани выводы в summary.md и приложи скриншот.

В журнале должны появиться действия браузера. Файлы можно скачать в блоке **Файлы результата**.

## Автономные задачи и субагенты

В **Настройках** включите вызов инструментов и задайте число субагентов от 0 до 3, число шагов и общий лимит времени. Ноль отключает делегирование. Агент может сам выбрать независимые части задачи или запустить субагентов по прямой просьбе. Субагент выполняет до 12 запросов с инструментами и может читать файлы, исследовать публичные страницы и прикладывать промежуточные результаты. Координатор меняет файлы VPS, проверяет выводы и выдаёт итог.

> Раздели работу между двумя субагентами. Первый пусть прочитает notes.txt и выделит главные идеи. Второй пусть найдёт в том же файле открытые вопросы. Собери их результаты, сохрани отчёт в reports/summary.md и приложи его для скачивания.

Страница задачи показывает план и ход работы. В Telegram команда `/result 12` показывает статус, субагентов и итог задачи №12. Остановка основной задачи останавливает её активных субагентов.

Запущенная задача работает после закрытия панели. Если сервер перезапустится, агент продолжит с последнего сохранённого действия и использует уже готовые результаты субагентов. Текущее незавершённое действие может быть запущено повторно. Браузерные вкладки открываются заново. Время простоя входит в общий лимит задачи.

## Файлы на VPS

При стандартном запуске постоянная папка `/workspace` хранится в Docker-томе `agent_workspace`. Дайте агенту относительный путь вроде `notes.txt` или `reports/summary.md`. Текстовые файлы можно читать частями по мере необходимости. Файлы до 8 МБ можно прочитать, перенести из вложений, сохранить в папке или приложить к результату. Для обновления существующего файла агент сначала читает текущую версию.

Положить файл в папку и забрать отчёт можно с VPS из каталога проекта.

```bash
docker compose cp ./notes.txt app:/workspace/notes.txt
docker compose cp app:/workspace/reports/summary.md ./summary.md
```

Для доступа к обычной папке VPS подключите её к контейнеру. Подготовьте отдельный каталог для материалов проекта и задайте путь `ASTER_HOST_WORKSPACE=/srv/aster-workspace` в `.env`.

```bash
sudo install -d -o 10001 -g 10001 -m 0750 /srv/aster-workspace
docker compose -f compose.yaml -f compose.workspace.yaml --profile https up -d --build
```

При смене подключения файлы из стандартного тома можно заранее забрать через `docker compose cp`. В режиме без публичного HTTPS уберите `--profile https` из команды запуска. Доступ ограничен выбранной папкой. Модель получает запрошенные фрагменты её файлов через настроенный API. [Подключение томов в Compose](https://docs.docker.com/reference/compose-file/merge/)

## Режим без публичного HTTPS

При настройке оставьте поле публичного адреса пустым. Запустите `docker compose up -d --build`. Панель будет доступна на VPS по `http://127.0.0.1:8000`. Для доступа с другого устройства откройте SSH-туннель:

```bash
ssh -L 8000:127.0.0.1:8000 user@ВАШ_IP
```

Затем откройте `http://127.0.0.1:8000` у себя. Бот может принимать задачи в этом режиме, если введён токен. Для кнопки Mini App потребуется HTTPS.

## Управление из Telegram

| Действие | Как вызвать |
|---|---|
| Поставить задачу | Сообщение или файл с подписью |
| Список задач | `/jobs` |
| Статус субагентов, ответ и файлы | `/result 12` |
| Остановить | `/stop 12` |
| Панель | `/panel` |

Бот работает через long polling и принимает команды только в личном чате владельца. Для него нужен токен нового бота или бота без активного webhook и второго запущенного экземпляра. При завершении задачи из чата бот отправляет уведомление. Панель показывает задачи из обоих интерфейсов.

## Данные и обслуживание

Настройки, задачи и вложения хранятся в Docker-томе `agent_data`. API-ключ из панели хранится в базе в зашифрованном виде. Храните резервные копии `.env`, базы и рабочей папки. Сервер использует `DATA_SECRET` из `.env` для чтения настроек. Программа отправляет подключённой модели содержимое задачи, выдержки из вложений и изображения при включённом анализе.

Для обновления существующей установки распакуйте файлы в каталог прежней версии, используйте существующий `.env` и пересоберите сервисы. Таблицы прогресса и субагентов создаются при запуске. Активные задания, запущенные старой версией, можно повторить из истории.

```bash
docker compose --profile https logs --tail=100 app browser caddy
docker compose --profile https up -d --build
```

Если поставщик API вернул HTTP 401, проверьте ключ. При 404 проверьте Base URL и модель. При 400 на задаче с файлами или браузером проверьте поддержку инструментов и изображений. При ошибке сертификата проверьте, что домен указывает на VPS или введён его публичный IP, а порты 80 и 443 доступны извне.

Локальные тесты запускаются после установки зависимостей командой `python3 -m unittest discover -s tests -v`.
